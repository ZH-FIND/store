# 基于Trae的团队AI Coding实操

你将基于提供的 CoffeeFlow V0 项目和 SQL 脚本，继续完成 V1 的需求扩展。

[coffeeflow\-v0\.zip](图片和附件/coffeeflow-v0.zip)

本次实操由团队共同完成。每组围绕一个共享项目开展工作，并最终交付一个可以运行和验收的版本。如何理解需求、组织协作、使用 Trae 和推进开发，由团队自行决定。

## 你拿到的 V0

- 有一个可运行的门店订单看板前端页面

- 可以查看订单列表、订单详情和基础筛选

- 可以更新订单状态

- 后端已经提供订单查询和订单状态更新接口

- 已经提供 MySQL 建库、建表和初始化数据脚本

- 项目已经具备本地运行和基本测试能力

项目采用以下技术栈：

- Java 17

- Spring Boot 3\.3

- JdbcTemplate

- Maven 3\.9\+

- MySQL 8 Community

- Vue 3

开始开发前，请先运行 V0，确认已有页面、接口和数据库能够正常工作。

## 你要完成的 V1

请基于现有 CoffeeFlow，增加面向顾客的线上下单能力和面向门店的商品管理能力。

本次需求至少包括：

- 顾客查看商品、价格和可售状态

- 顾客选择取餐门店

- 顾客在一个订单中选择一个或多个商品及数量

- 顾客提交订单

- 系统返回订单金额和取餐码

- 顾客通过取餐码查询订单

- 顾客在门店开始制作前取消订单

- 门店停售或恢复商品

- 原有 V0 门店订单看板继续正常使用

## 用户故事

### 用户故事一：顾客浏览商品

作为顾客，我希望查看当前商品、价格和可售状态，以便选择想要购买的饮品。

### 用户故事二：顾客提交订单

作为顾客，我希望选择取餐门店，在一个订单中选择一个或多个商品及数量并提交订单，以便提前完成点单。

下单成功后，系统需要返回订单金额和取餐码。

### 用户故事三：顾客查询进度

作为已经下单的顾客，我希望通过取餐码查询订单详情和最新状态，以便合理安排到店取餐时间。

### 用户故事四：顾客取消订单

作为已经下单的顾客，我希望在门店开始制作前取消订单，以便在行程发生变化时及时终止制作。

### 用户故事五：门店管理商品状态

作为门店店员，我希望临时停售或恢复商品，以便在商品缺货时及时停止接收新订单。

## 你需要怎么做

请解压提供的 V0 项目，以团队第一次接手现有项目的方式开始。

团队需要先运行系统、阅读现有代码和 SQL，理解 V0 的业务和技术现状，再决定如何完成 V1。

每组使用一个共享代码仓库，最终提交一个团队共同完成的集成版本，不提交多套个人版本。

团队可以自由使用 Trae 完成：

- 阅读和理解现有项目

- 分析业务需求

- 修改前后端代码

- 修改数据库结构

- 编写 SQL 脚本

- 调试运行问题

- 验证最终结果

**业务要求不明确时，可以向业务方提问。**团队需要自行决定如何记录已经确认的信息、设计选择和验证结果。

最终结果以系统真实运行和业务方验收为准。

## Verification Gate（验证门禁）

- **不允许**在无验证证据的情况下宣称“已完成/已修复/已通过”。
- 变更最小验证集（MUST）：
